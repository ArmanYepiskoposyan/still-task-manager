# Phase 4 audit

Audit started 2026-10-27 against the independently approved Phase 3 implementation. Baseline hashes of all 103 review files were recorded before editing application code. Synthetic browser contexts only; no personal tasks were read. Findings below were documented before their corrections.

## Audit boundaries and preliminary non-defects

The synchronous committed-state cursor prevents rapid commands from losing prior successful mutations before React renders. Repository commits re-read and validate storage, compare the expected raw document, serialize/validate the candidate, write, and only then publish. Failed writes preserve committed tasks and open drafts. Unsupported/corrupt documents block writes. IDs, timestamps and completion invariants are validated. No schema change is warranted.

Native dialog cleanup and opener restoration were inspected. Manual keyboard checks in the desktop app's local browser confirmed the skip link, opening with Enter, initial title focus, blank-title feedback, reverse Tab trapping, forward wrap and Escape returning focus to New task. This is an agent-operated manual UI check, separate from scripted Playwright assertions; it is not a screen-reader test.

Cross-tab raw-snapshot comparison is best effort, not a transaction: another writer can intervene between getItem and setItem. Same-tab custom scripts can also modify storage. This remains a documented platform limitation, not a claim of synchronization. Tasks remain local and unencrypted. Backup/restore belongs to Phase 5 and is not implemented here.

No changes to branding, schema, domain commands, reducer or working modal architecture are planned. Additional audit coverage and final results follow in the completed report.

### R2 — confirmed during expanded tests, before correction

Low severity: the new round-trip determinism test fails on the approved serializer. A newly created task serializes in construction-property order, while the same task after reload serializes in deserializer-property order. Values and task order are unchanged, but byte serialization is not stable through round trips. The planned correction is one shared known-field projection for reading and writing, preserving schema version 1, valid historical data, optional fields and raw-snapshot conflict comparisons. This also prevents unknown fields from being propagated by the serializer. No migration or automatic rewrite on load is needed.

## Reliability and data-safety assessment

- **Identity and rapid actions:** stable IDs and the synchronous committed cursor are retained. Expanded testing injects failure into the middle of three synchronous creates, checks the UI is not published before writes, and verifies the following command uses the last successful snapshot. Repeated completion/reopening preserves identity. Existing double-submit, no-op edit and cancellation assertions remain.
- **Stale dialogs:** an edit or deletion dialog opened before another tab deletes its task must fail safely, retain the edit draft, preserve the external snapshot, then recover through explicit reload. No automatic merging is attempted.
- **Corruption and unexpected structures:** tests cover malformed JSON, scalar/array documents, unsupported versions, duplicate IDs, wrong field types, bad chronology, impossible dates and oversized fields. Repository validation still precedes writes; failures leave raw data untouched.
- **Recovery:** unavailable reads and quota/blocked writes remain explicit. Successful Retry/reload restores usable keyboard focus. Reload never silently replaces corrupt data. Unknown schema versions are preserved.
- **Dates and selection:** the existing local-date hook, literal Unicode search, AND filters, copied sorting, counts and Today rules remain. Deadline formatting now reuses a formatter with explicit calendar fields in a display-only UTC container; local classification never uses that container. Tests include leap days, years 1/99/9999 and UTC+14/UTC−11 display. Existing midnight/focus tests remain.
- **Themes:** persistence, System media-query handling, early theme application and honest save failures remain covered. Theme preference does not trigger a task-conflict warning.
- **Architecture:** pure domain commands and selectors, reducer/context ownership, editor-local drafts and repository boundaries remain. The repository only gains a shared field projection. No broad component refactor, schema migration, dependency, virtualization or new state library is introduced. Historical unused prototype CSS is not removed speculatively during this focused audit.

## Security and dependencies

Task text is rendered as React text nodes or input/textarea values. No HTML injection API, eval or user-content execution path was found. Browser tests save and reload HTML/script-looking titles/notes and mixed Unicode as literal text, and confirm no injected node/global appears. Stored JSON is validated and only known task fields propagate; prototype-like fields do not pollute objects. Title/notes limits remain 200/5,000 UTF-16 code units. Literal search treats regex syntax as text; Unicode normalization does not execute input.

`npm audit --json` reported zero known vulnerabilities (all severities zero) on 2026-10-27. The [registry response](measurements/phase4-dependency-audit.json) is included. `npm ls --all --json` succeeded. All direct installed versions match the manifest and lockfile exactly. `npm audit signatures` verified registry signatures for 254 installed packages and attestations for 110; this does not assert that all registry packages provide attestations. `npm cache verify --cache .npm-cache` verified 548 cached content entries. No dependency update was indicated by this audit and the lockfile is unchanged.

No high-severity functional or data-integrity defect has been confirmed. Remaining risks include origin-level access to unencrypted localStorage, site-data deletion/quota, synchronous large-document writes, and the non-transactional concurrent-write window. There is no import UI; tests of imported-like objects exercise the stored JSON boundary. Very large or manually corrupted documents can still consume main-thread time; the app makes no unlimited-size guarantee. Dependency reports are point-in-time evidence, not a guarantee against unknown vulnerabilities. No public deployment or Phase 5 backup/restore is implemented.

### Verification-harness findings

The expanded run also confirmed three harness weaknesses: a virtual clock could advance past midnight before navigation finished (or past a same-instant pause target in WebKit); Firefox's float bounding boxes can report 43.99994 for a 44px box; and the new contrast calculator initially did not expand minified `#fff`. Corrections preserve the same calendar, 44px and contrast requirements. The 26-image evidence scenario exceeded Playwright's default 30-second test budget under load; its scenario timeout is increased to 90 seconds without dropping captures or assertions. These are test-harness corrections, separate from application defects.

The follow-up diagnostic also exhausted the default 30-second scenario budget in the retained cross-tab test, after its task-count assertion had completed and during page cleanup. The suite includes multi-page workflows and repeated axe scans; its overall per-test budget is now 60 seconds, with 90 seconds for the 26-image evidence scenario. Assertion timeouts and all functional assertions remain unchanged. Performance is measured separately, so a larger functional-test budget is not presented as a performance improvement. The diagnostic was stopped before another complete run with these budgets.

## Final disposition

R1, A1, V1 and R2 are corrected and covered by passing regression tests. P1's repeated formatter construction is removed; an alternating approved/current build comparison shows approximately 11–12% lower median rendering times at the measured sizes, while substantial run-to-run variability and large-list cost remain documented. No unresolved high-severity functional or data-integrity defect was found in the audited scope.

The complete final suite passes 212 unit/component tests and 177 browser executions, with six duplicate capture skips and no functional skips. All 156 axe scans and the explicit contrast/reflow checks pass. See [verification](phase4-verification.md) for exact commands, samples, intermediate failures and limits, and [visual review](phase4-visual-review.md) for 26 actual before/after evidence images. The 42 historical screenshots remain unchanged. Phase 5 requires explicit authorization.
